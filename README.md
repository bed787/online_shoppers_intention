# Прогнозирование намерений онлайн-покупателей (Online Shoppers Purchasing Intention)

## 1. Почему именно этот датасет

* **Наличие дисбаланса классов:** Так как пользователей, сделавших хотя бы одну покупку, гораздо меньше, возникает дисбаланс классо. Это вынуждает работать с нестандартными метриками качества.
* **Разнообразие признаков:** Присутствуют как числовые, так и категориальные переменные. Это позволяет полноценно применить пайплайн подготовки данных.
* **Понятная бизнес-логика:** Поведение пользователей в сети интуитивно понятно, что позволяет строить нетривиальные и логичные гипотезы.

**Датасет:** [Online Shoppers Intention](https://www.kaggle.com/datasets/imakash3011/online-shoppers-purchasing-intention-dataset)

## 2. Гипотезы

Перед началом моделирования были выдвинуты следующие гипотезы:
1. Более длительное взаимодействие с product-related страницами связано с большей вероятностью покупки.
2. Из-за сильного дисбаланса классов метрика Accuracy может быть малоинформативной; при оценке моделей критически важны Recall, Precision, F1 и PR-AUC.
3. Модель Decision Tree может описывать нелинейные поведенческие паттерны лучше линейного baseline (проверяется на валидации).
4. Признак `PageValues` содержит очень сильный сигнал для `Revenue`. Построение baseline-модели только на `PageValues` позволит оценить, насколько много информации даёт этот признак сам по себе.
5. Использование параметра `class_weight='balanced'` в Logistic Regression изменит компромисс Precision/Recall (направление и величина эффекта проверяются экспериментально).

## 3. Результаты разведочного анализа (EDA)

* **Целевая переменная (`Revenue`):** 10 422 сессий (84.5%) завершились без покупки, и только 1 908 (15.5%) — с покупкой. Сильный дисбаланс классов подтвержден.
* **Пропуски и дубликаты:** 
  * Пропусков в данных нет.
  * Обнаружено 125 полных дубликатов. Принято решение **сохранить** их: так как отдельного идентификатора сессии нет, это могут быть независимые сессии с одинаковыми характеристиками. Их удаление изменило бы распределение целевой переменной.
* **Распределения числовых признаков:** Большинство признаков активности имеют сильный скос вправо. Основная масса сессий имеет небольшие значения, но есть и экстремальные выбросы.
* **Особая роль `PageValues`:** У 77.9% (9600) сессий ценность страниц равна 0. При этом конверсия в группе `PageValues > 0` составляет впечатляющие 56.3%, а в группе с нулевым значением — всего 3.9%.
* **Категориальные признаки:** Для признаков `Browser`, `OperatingSystems` и `TrafficType` характерно наличие доминирующих категорий и длинного хвоста редких значений.

## 4. Инженерия признаков (Feature Engineering)

В ходе анализа корреляций и подготовки данных были приняты следующие решения:

1. **`ProductRelated` и `ProductRelated_Duration`:**
   * Признаки логично коррелируют между собой.
   * Создан новый признак средней длительности просмотра одной страницы: `Avg_Product_Duration`. Чтобы избежать искажений, для `ProductRelated == 0` значение устанавливается строго в `0.0`, без искусственного добавления единицы в знаменатель.
2. **`BounceRates` и `ExitRates`:**
   * Между метриками наблюдается высокая степень корреляции. Для базового ML-решения решено оставить `ExitRates` и исключить `BounceRates`, чтобы уменьшить дублирование информации.
3. **Редкие категории:** 
   * Для предотвращения переобучения и борьбы с разреженностью планируется объединить редкие значения категориальных переменных в группу `Other` (частоты рассчитываются исключительно по тренировочной выборке).

## 5. Планы по машинному обучению (Machine Learning)

На следующих этапах проекта планируется обучение и сравнение нескольких алгоритмов:
* **Logistic Regression:** в качестве интерпретируемого линейного бейзлайна. Будет исследовано влияние гиперпараметра `class_weight='balanced'` на смещение баланса между полнотой и точностью.
* **Decision Tree:** для выявления нелинейных взаимосвязей в поведении пользователей.
* **CatBoost:** мощный алгоритм градиентного бустинга, отлично работающий "из коробки" с категориальными переменными, который должен показать наилучшую обобщающую способность. 

Для объективной оценки моделей в условиях дисбаланса упор будет сделан на метрики Precision, Recall, F1-score и PR-AUC.
